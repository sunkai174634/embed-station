# Architecture

HTTP input validation -> bounded asynchronous batch worker -> tokenizer and GPU inference engine -> response. `settings` owns environment configuration; `inference` owns OpenVINO/tokenizer; `batch` merges independent text submissions and resolves each waiter separately; `api` validates HTTP/contracts and lifecycle; `telemetry` owns SQLite and stdout JSON; `static` is a same-origin, dependency-free dashboard.

`OpenVINOEngine` checks for the literal `GPU` device, compiles IR only there, and performs an initialization probe before ready. Tokenization uses the local tokenizer with truncation disabled. Left padding matches the Qwen tokenizer configuration; pooling selects the last padded position (the final valid token under left padding) and L2-normalizes. Batch result association follows positional order. On the target N150/OpenVINO stack, concurrent `AsyncInferQueue` callbacks reproducibly crashed while reading request output. The service therefore uses one synchronous `InferRequest` protected by a mutex; HTTP workers and CPU tokenization may run concurrently, but GPU inference is deliberately serialized. Shutdown waits for an in-flight inference before releasing the engine. Do not raise the inference concurrency without revalidating on the target driver/runtime.

SQLite uses synchronous short transactions in worker threads with parameterized query filters, an index on time ordering, and maximum 100 rows per page. Only request metadata and error class are persisted; raw inputs, vectors, and free-form exception messages are excluded. API returns a generic inference error while server logs carry the request ID and exception traceback. Browser fields are assigned with `textContent`, never interpolated into HTML. Canceled callers are not allowed to cancel shared work; batch worker skips canceled futures. On shutdown, new requests stop, the worker is canceled, and GPU requests are waited on.

`/health` indicates process liveness; `/ready` requires a loaded engine and successful GPU probe. Model/GPU failure is startup failure and never triggers CPU fallback. The tested NAS container mounts the host Intel compiler stack read-only (`/usr/local/lib` at `/hostlocal`, without covering container package paths), device nodes, and video/render groups; compose requires host-provided group IDs and library paths to be verified per target host.
